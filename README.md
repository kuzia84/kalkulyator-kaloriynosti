# Калькулятор калорийности блюда

Адаптивное веб-приложение (PWA) для телефона и компьютера. Оно считает калорийность и БЖУ готового блюда с учётом уварки.

Сайт: https://kuzia84.github.io/kalkulyator-kaloriynosti/

## Что умеет

- Таблица ингредиентов: название с подсказками, вес, ккал, белки, жиры, углеводы. Расчёт идёт сразу при вводе.
- Строки «Итого», «На 100 г блюда» и «На 100 г готового блюда (с учётом уварки)» с полем веса готового блюда.
- Справочник продуктов на устройстве: стартовый набор по таблицам Скурихина, ранги популярности, новые продукты после первого использования.
- Поиск в Open Food Facts и USDA FoodData Central, если есть интернет. Без интернета — только справочник.
- Поиск по штрихкоду: фото, камера или цифры кода. Распознавание идёт на устройстве.
- Страница модерации справочника: поиск, сортировка, фильтры, добавление продукта (вручную, по штрихкоду или поиском в сети), правка, удаление с отменой.
- «Мои рецепты» с правкой состава и веса ингредиентов, расчёт порции, диаграмма БЖУ, экспорт CSV, печать, перенос данных файлом JSON, светлая и тёмная тема.
- Работа без интернета и установка на телефон и компьютер.

## Запуск

Нужен Node.js 22.

```bash
npm ci --maxsockets 4 --no-audit --no-fund
npm run dev          # http://localhost:5173
```

В режиме разработки в «Настройках» есть блок «Для разработки». Кнопка «Добавить тестовые рецепты» кладёт в «Мои рецепты» 6 блюд из стартового справочника. Повторное нажатие заменяет их, а не дублирует. В production-сборку этот блок не попадает.

## Сборка и развёртывание

```bash
npm run build        # папка dist
npm run preview      # проверка сборки на http://localhost:4173
```

Сборка для подпапки задаётся переменной `BASE_PATH`, например `BASE_PATH=/kalkulyator-kaloriynosti/ npm run build`.

Каждый пуш в `main` публикует сайт на GitHub Pages: workflow `.github/workflows/deploy.yml`. Камера на iPhone работает только по HTTPS, GitHub Pages его даёт.

## Версии и обновление

- Пользователь видит версию как дату сборки в формате дд.мм.гг, например «версия от 11.11.26», и номер сборки рядом. Обе части меняются сами при каждом выпуске. Дата считается по московскому времени, поэтому одна сборка у всех называется одинаково. Поле `version` из `package.json` тоже попадает в `version.json`. Пользователь видит его только тогда, когда у сборки нет даты.
- Номер сборки — короткий SHA коммита (`GITHUB_SHA` в CI), локально — время сборки. Сборка кладёт в `dist` файл `version.json` с версией, номером и временем сборки.
- Приложение раз в сутки запрашивает `version.json` в обход кэша. Если на сервере сборка новее, у пункта «Настройки» появляется оранжевый «!», а кнопка «Обновить приложение» в начале настроек выделена.
- «Обновить приложение» включает скачанную новую версию service worker и перезагружает страницу. Если новый service worker ещё не скачан, кнопка сбрасывает кэш и перезагружает страницу.
- «Сбросить кэш и перезагрузить» удаляет сохранённые файлы приложения. Справочник, рецепты, черновик и настройки в IndexedDB остаются.

## Ключ USDA

Поиск в USDA FoodData Central требует бесплатный ключ: https://fdc.nal.usda.gov/api-key-signup.

1. Откройте «Настройки».
2. Вставьте ключ в поле «Ключ USDA API».
3. Нажмите «Сохранить».

Ключ хранится только в IndexedDB этого браузера. Он не попадает в код, в репозиторий и в файл переноса данных.

## Облако: Google Диск и Яндекс Диск

В «Настройках» → «Перенос данных» можно войти в Google или Яндекс и нажать «Выгрузить в облако». На другом устройстве — войти в тот же аккаунт и нажать «Загрузить из облака». Если на устройстве уже есть рецепты, приложение спрашивает: объединить или заменить. Копия одна, каждая выгрузка пишет поверх прежней. Если копию записало другое устройство, приложение перед выгрузкой спрашивает, записать ли поверх. Настройки и ключ USDA в копию не входят.

Сервера у приложения нет. Вход идёт по OAuth 2.0 implicit flow: браузер получает токен сразу, без client secret. Токен хранится в `localStorage` этого браузера.

| Сервис      | Где лежит файл                                              | Доступ приложения                                               | Срок входа               |
| ----------- | ----------------------------------------------------------- | --------------------------------------------------------------- | ------------------------ |
| Google Диск | `kalkulyator-kaloriynosti.json` в корне Диска               | `drive.file`: только файлы, которые создало приложение, и почта | 1 час, потом войти снова |
| Яндекс Диск | `Приложения/<имя приложения>/kalkulyator-kaloriynosti.json` | папка приложения на Диске и почта                               | около года               |

Кнопка входа появляется, только когда в сборке задан client ID сервиса. Без client ID приложение работает как раньше.

### Google

1. Откройте https://console.cloud.google.com/, создайте проект.
2. Включите **Google Drive API** (APIs & Services → Library).
3. Настройте экран согласия (OAuth consent screen): тип External, scope `.../auth/drive.file` и `email`. Пока приложение в режиме Testing, войти могут только тестовые пользователи из списка. Для всех — нажмите Publish app.
4. Создайте OAuth client ID типа **Web application**:
   - Authorized JavaScript origins: `https://<логин>.github.io` и `http://localhost:5173`.
   - Authorized redirect URIs: `https://<логин>.github.io/kalkulyator-kaloriynosti/` и `http://localhost:5173/` — с косой чертой в конце.
5. Скопируйте Client ID.

### Яндекс

1. Откройте https://oauth.yandex.ru/client/new, платформа «Веб-сервисы».
2. Redirect URI: `https://<логин>.github.io/kalkulyator-kaloriynosti/` и `http://localhost:5173/`.
3. Доступы: «Яндекс Диск» → «Доступ к папке приложения на Диске» (`cloud_api:disk.app_folder`), «Яндекс ID» → «Доступ к адресу электронной почты» (`login:email`).
4. Скопируйте ClientID.

### Куда записать client ID

- Локально — файл `.env.local` в корне (в git не попадает):
  ```
  VITE_GOOGLE_CLIENT_ID=...apps.googleusercontent.com
  VITE_YANDEX_CLIENT_ID=...
  ```
- Для GitHub Pages — Settings → Secrets and variables → Actions → **Variables**: `VITE_GOOGLE_CLIENT_ID`, `VITE_YANDEX_CLIENT_ID`. Client ID не секрет: он всё равно виден в коде страницы.

iCloud и Облако Mail.ru пока не поддерживаются. Для iCloud нужен платный Apple Developer и CloudKit. У Облака Mail.ru нет открытого API для сайта без сервера.

## Допущения и риски

- **Стартовый набор.** У таблиц Скурихина нет API и открытой машиночитаемой версии. Значения 54 продуктов взяты из справочника «Химический состав российских пищевых продуктов» (Скурихин И. М., Тутельян В. А., 2002). Каждая запись проходит проверку `Б×4 + Ж×9 + У×4` с отклонением не больше 15 %. Записи получают признак «не проверено»: модератору стоит сверить их с печатным изданием и отметить.
- **Строка без продукта.** Вес строки, где продукт не выбран, не входит в «Итого». Иначе «на 100 г» занижалось бы весом без калорий.
- **Калорийность не сходится с БЖУ.** Справочник отмечает запись, если указанная калорийность отличается от расчётной по `Б×4 + Ж×9 + У×4` больше чем на 15 % и не меньше чем на 5 ккал. Порог в 5 ккал убирает ложные срабатывания у малокалорийных продуктов (чай, зелень).
- **Open Food Facts.** Новый поиск `search.openfoodfacts.org` не отдаёт заголовок CORS, поэтому приложение использует `world.openfoodfacts.org/cgi/search.pl`. Этот сервис временами отвечает 503 без заголовка CORS (проверено 11.11.2026). Тогда браузер блокирует ответ, а приложение показывает подсказки справочника и пояснение «Не ответил: Open Food Facts». Лимиты OFF — 10 запросов поиска и 15 запросов продукта в минуту с IP. Данные под ODbL. Браузер не даёт задать свой `User-Agent`.
- **USDA.** 1000 запросов в час с ключа, приложение берёт не больше 16 в минуту. Названия на английском. Данные — CC0.
- **`BarcodeDetector`** нет в Safari на iPhone и в Firefox, там работает ZXing. ZXing распознаёт хуже на смазанных фото. Тогда приложение просит переснять или ввести цифры.
- **Камера** требует HTTPS и разрешение пользователя. Без разрешения работает загрузка фото.
- **Safari на iPhone** может удалить данные сайта, который не открывали 7 дней, если сайт не установлен на главный экран. Установите приложение или сохраняйте файл переноса данных.
- **Хранение.** Данные живут в одном браузере. Перенос между устройствами — файлом JSON или копией в Google Диске и Яндекс Диске вручную. Автоматической синхронизации нет.
- **Облако.** Google считает implicit flow устаревшим, но для сайтов без сервера он работает. Ссылки Яндекс Диска на запись и чтение файла ведут на другие серверы Яндекса. Их ответы CORS проверены только частично, без реального токена.
