# Требования

Список собран из раздела Context мастер-промпта. Номера используются в `docs/requirements-check.md`.

## Платформа

1. Адаптивное одностраничное веб-приложение (SPA) для Windows, Android и iPhone.
2. Приложение устанавливается как PWA и работает без интернета.
3. Язык интерфейса — русский.
4. Десятичная дробь вводится через запятую и через точку.
5. Числа показываются в русском формате (`Intl.NumberFormat('ru-RU')`).
6. Ключи API не хранятся в коде. Пользователь задаёт их в настройках.

## Таблица

7. Таблица имеет 6 столбцов: наименование, вес (г), ккал, белки (г), жиры (г), углеводы (г).
8. При открытии таблица показывает 1 строку ингредиента.
9. Поле ввода названия есть только в столбце 1.
10. После ввода одной или нескольких букв появляется список продуктов, чьё название начинается с этих букв.
11. Список показывает до 5 продуктов. При большем числе совпадений список прокручивается.
12. Пользователь выбирает продукт из списка мышью, касанием или клавиатурой (↑, ↓, Enter, Escape).
13. После ввода веса столбцы 3–6 строки обновляются сразу, без кнопки «Рассчитать».
14. Кнопка «Добавить ингредиент» добавляет одну строку. Новая строка работает как строка 1.
15. Строка «Итого» показывает общий вес и суммы ккал и БЖУ.
16. Строка «На 100 г блюда» показывает ккал и БЖУ на 100 г по сумме весов.
17. Строка «На 100 г готового блюда (с учётом уварки)» содержит поле веса готового блюда и показывает ккал и БЖУ на 100 г по этому весу. Суммы не меняются. Если вес готового блюда задан, карточка с диаграммой БЖУ показывает значения на 100 г готового блюда.
18. Порядок блоков: строки, кнопка, «Итого», «На 100 г блюда», строка уварки.

## Расчёт

19. `ккал_строки = ккал_на_100 × вес / 100`, то же для БЖУ.
20. Итоги — суммы по всем строкам.
21. `ккал_100 = ккал_итого / вес_итого × 100`, то же для БЖУ.
22. `ккал_100_готов = ккал_итого / вес_готового × 100`, то же для БЖУ.
23. Ккал округляются до целого (0,5 — вверх), БЖУ — до 0,1.
24. Округление только при показе. Расчёт хранит полную точность.
25. Если вес итого или вес готового блюда равен нулю или пуст, ячейка показывает «—».
26. Если вес готового блюда больше суммы весов, калькулятор принимает его и показывает пояснение, а не ошибку.

## Справочник

27. Приложение ведёт собственный справочник без ограничения размера.
28. Стартовый набор — по таблицам Скурихина. Значения не придумываются. Нет точного значения — нет продукта.
29. Вода (0 ккал, 0 г БЖУ) входит в стартовый набор.
30. Запись: название, ккал, белки, жиры, углеводы на 100 г, штрихкод, источник, ранг популярности, дата последнего использования, признак «проверено».
31. Ранг растёт при использовании продукта. Подсказки сортируются по рангу.
32. Новый продукт попадает в справочник, когда строка блюда содержит продукт и вес больше нуля.
33. Значения даны на 100 г сырого съедобного продукта.
34. Блюдо хранит копию значений каждого ингредиента. Правки справочника не меняют сохранённые блюда.
35. Формула `Б × 4 + Ж × 9 + У × 4` используется только для проверки записей.

## Поиск

36. Поиск по справочнику работает всегда, в том числе без интернета.
37. Поиск не учитывает регистр, считает «е» и «ё» одной буквой и ищет совпадение с началом названия.
38. При наличии интернета поиск идёт также во внешних источниках (Open Food Facts, USDA FoodData Central).
39. Запрос к внешним источникам идёт с задержкой после ввода. Устаревший запрос отменяется.
40. Ошибка сети не ломает подсказки из справочника.
41. Результаты внешних источников отмечены в списке.
42. Если продукт не найден, пользователь вводит название, ккал и БЖУ вручную.
43. Без интернета приложение показывает сообщение «поиск только по справочнику». Сообщение не блокирует работу.

## Штрихкод

44. Пользователь загружает фото штрихкода из галереи или снимает камерой.
45. Форматы: EAN-13, EAN-8, UPC-A, UPC-E.
46. Если нет `BarcodeDetector`, работает запасная библиотека (ZXing). Фото не уходит на сервер.
47. Поиск по коду: сначала справочник, потом внешние источники.
48. Если код не распознан, приложение просит сделать новое фото или ввести код вручную.

## Модерация

49. Таблица всех продуктов с поиском и сортировкой.
50. Фильтры: источник, «проверено», подозрительная калорийность (отклонение от формулы больше 15 %).
51. Модератор редактирует запись, удаляет её и ставит «проверено».
52. Удаление спрашивает подтверждение и допускает отмену.
53. Модератор объединяет дубликаты в одну запись.

## Хранение

54. Таблица сохраняется между открытиями.
55. Черновик текущего блюда сохраняется автоматически при каждом изменении.
56. Сравнить варианты хранения и выбрать основной.

## Дополнительные функции

57. Оценить предлагаемые функции, разделить на «первая версия» и «план», реализовать первую версию.

## Тесты

58. Модульные тесты расчёта и поиска: контрольный пример, ноль, пустое поле, десятичная запятая, округление 0,5.
59. Сквозные тесты: ввод продукта, ввод веса, ввод веса готового блюда, перезагрузка страницы.
