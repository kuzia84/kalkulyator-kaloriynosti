# Архитектура

## Стек

| Часть    | Выбор                                                  | Почему                                                                  |
| -------- | ------------------------------------------------------ | ----------------------------------------------------------------------- |
| Язык     | TypeScript (strict)                                    | Типы ловят ошибки в формулах и схеме данных до запуска.                 |
| UI       | React 18                                               | Однонаправленный поток данных, большой набор инструментов для тестов.   |
| Сборка   | Vite 5                                                 | Быстрая сборка, готовый плагин PWA.                                     |
| Хранение | Dexie 4 поверх IndexedDB                               | Индексы, транзакции и миграции схемы без своего кода поверх сырого API. |
| PWA      | vite-plugin-pwa (Workbox)                              | Service worker и манифест генерируются при сборке.                      |
| Штрихкод | `BarcodeDetector`, запасной вариант — `@zxing/browser` | В Safari на iPhone и в Firefox нет `BarcodeDetector`.                   |
| Тесты    | Vitest, Testing Library, fake-indexeddb, Playwright    | Модульные тесты в jsdom, сквозные — в настоящем браузере.               |
| Хостинг  | GitHub Pages                                           | Статика по HTTPS. Камера на iPhone работает только по HTTPS.            |

Маршруты — hash (`#/`, `#/recipes`, `#/moderation`, `#/settings`). GitHub Pages не умеет отдавать `index.html` на любой путь, а hash-маршрут этого не требует.

## Модули

```text
                    ┌──────────────────────────────┐
                    │ ui/  (страницы, таблица,     │
                    │      combobox, формы)        │
                    └──┬─────────┬─────────┬───────┘
                       │         │         │
          ┌────────────▼──┐  ┌───▼──────┐  ┌▼─────────────┐
          │ calc/         │  │ search/  │  │ barcode/     │
          │ чистые        │  │ OFF,USDA,│  │ Detector,    │
          │ функции       │  │ debounce │  │ ZXing        │
          └───────────────┘  └───┬──────┘  └┬─────────────┘
                                 │          │
                       ┌─────────▼──────────▼──┐
                       │ catalog/ справочник,  │
                       │ поиск, ранги, сид     │
                       └─────────┬─────────────┘
                                 │
     ┌─────────────────┐  ┌──────▼──────────────────┐
     │ moderation/     ├──► storage/ Dexie, черновик,│
     │ (страница)      │  │ рецепты, настройки, JSON │
     └─────────────────┘  └─────────────────────────┘
```

- `calc/` не знает про React и IndexedDB. Это чистые функции: вход — числа, выход — числа или `null`.
- Состояние блюда живёт в `useReducer`. Каждое действие даёт новое состояние, расчёт идёт из состояния при каждой отрисовке.
- `storage/` сохраняет черновик после каждого изменения состояния.

## Схема данных

Версия схемы — `1`. Dexie хранит номер версии сам. Новая версия объявляется через `db.version(n).stores(...).upgrade(tx => ...)`. Функция `upgrade` переводит старые записи в новый формат в той же транзакции.

```ts
interface Nutrients {
  kcal: number;
  protein: number;
  fat: number;
  carbs: number;
} // на 100 г

interface Product extends Nutrients {
  id: string;
  name: string;
  nameNorm: string; // нижний регистр, «ё» → «е»; индекс для поиска по началу
  barcode?: string;
  source: 'skurikhin' | 'off' | 'usda' | 'user';
  rank: number; // растёт при каждом использовании
  lastUsedAt?: number; // мс от эпохи
  verified: boolean;
}

interface DishRow {
  id: string;
  productId?: string;
  name: string;
  weight: string; // как ввёл пользователь: «150», «12,5», ''
  per100?: Nutrients; // копия значений продукта
  source?: Product['source'];
}

interface Dish {
  id: string;
  name: string;
  rows: DishRow[];
  cookedWeight: string;
  portionWeight: string;
  note: string;
  createdAt: number;
  updatedAt: number;
}

interface Settings {
  suggestionsLimit: number; // сколько подсказок загружать
  sourcesOrder: ('off' | 'usda')[];
  usdaApiKey: string;
  theme: 'system' | 'light' | 'dark';
}
```

Таблицы Dexie: `products` (`id, nameNorm, barcode, source, rank, verified`), `drafts` (одна запись `current`), `recipes`, `settings` (одна запись `app`), `searchCache` (ответы внешних API).

## Хранение: сравнение

| Вариант                            | Без интернета | Между устройствами | Сервер и вход | Сложность                                       |
| ---------------------------------- | ------------- | ------------------ | ------------- | ----------------------------------------------- |
| 1. IndexedDB                       | да            | нет                | не нужны      | низкая                                          |
| 2. IndexedDB + синхронизация       | да            | да, автоматически  | нужны         | высокая: конфликты, аккаунты, стоимость сервера |
| 3. IndexedDB + экспорт/импорт JSON | да            | да, файлом вручную | не нужны      | низкая                                          |

**Выбран вариант 3.** Он даёт перенос данных между телефоном и компьютером без сервера, аккаунтов и персональных данных. Вариант 2 остаётся в плане: схема хранит `updatedAt` у блюд, это нужно для будущей синхронизации.

| ---------------------------------------------------------------------------------- | ------------------------------------------ | ----------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
